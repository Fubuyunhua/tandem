## 要检查的不变量（至少这些，可以补充）
1. **CI 守卫**：任何产生 `MERGE` 动作的决定，都发生在"当前提交编号的 CI 是绿的"之后。
2. **写审分离**：被计入"通过"的审核结论，其提供方都不在 `providers_involved` 里。
3. **多家审核**：多 Agent 模式下，非 D 级任务进入"待合并"时，有至少 `required_reviewers` 家**不同提供方**针对**当前提交编号**给出了通过的结论；或者是你明确的人工批准。
4. **终点不可逆**：进入已合并、已取消、失败以后，任何事件都不再改变任务。
5. **版本单调**：每次 `changed=True`，状态版本号正好加 1；`changed=False` 时，任务记录完全不变。
6. **D 级**：D 级任务进入"处理中"并交回代码之前，方案一定已经被批准；D 级永远不会不经过"待你审核"就进入"待合并"。
7. **纯函数**：同样的输入调用两次 `decide`，得到的结果完全相同。
8. **新提交作废旧证据**：提交编号变了以后，旧提交的审核结论不会再被计入通过。
