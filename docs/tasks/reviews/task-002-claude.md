# task-002 审核意见 · Claude

审核对象：`feat/wsl-isolation` 相对 `main` 的改动。本地跑过 ruff、pyright 和 pytest（32 个测试），全部通过。我还核实了 pi 只运行了只读命令，以及脚本的 `-DryRun` 模式：本机的 WSL 发行版没有变化，也没有生成 `.wslconfig`。

整体评价：判断逻辑写成了纯函数，把"没有执行"和"通过"区分开了，PowerShell 脚本有前提检查、确认步骤和 dry-run，做得扎实。问题出在**隔离的起点**：新发行版是从你现有的 Ubuntu 复制出来的，会把里面原有的东西一起带进去。

## 1.【高】从现有的 Ubuntu 导出再导入，会把你的私人数据一起复制进"隔离"发行版
- **位置**：`scripts/wsl/setup-tandem-distro.ps1:152-167`
- **为什么重要**：`wsl --export Ubuntu` 导出的是整个系统，你在 Ubuntu 里的家目录会被原样复制到 `tandem` 发行版里，包括 `~/.ssh` 私钥、`~/.git-credentials`、`gh` 和各家 AI 的登录令牌、shell 历史等等。这样一来，后台 Agent 不需要碰 Windows，在发行版内部就能读到真正的凭据。诱饵测试也查不出这个问题：诱饵是新放进去的，测试只检查 Agent 能不能读到诱饵，不会去检查那些原来就在的凭据。
- **建议**：用**干净的官方镜像**来建发行版，不要复制现有的 Ubuntu。
  - 一种办法是用官方的发行版安装命令，并指定一个新名字【未核实：当前版本的 WSL 是否支持在安装时指定名称】；
  - 另一种办法是下载 Ubuntu 官方的 WSL rootfs 镜像，校验哈希后再 `--import`。
  - 如果为了不联网，还是要保留"导出再导入"这种方式，至少要在导入之后清空 `/home/*` 和 `/root` 下的凭据文件，并在操作手册里把这一步列为必做。但这种清理很难做全，所以不推荐。

## 2.【中】"访问外网"这一项只测了本机端口，通过了也不代表外网真的被挡住
- **位置**：`scripts/decoy/run_decoy.py:86-102`（诱饵端口监听在 `127.0.0.1`）；`scripts/decoy/checks.py:137-151`
- **为什么重要**：这一项只能证明 Agent 没有连上本机的诱饵端口。如果 Agent 连的是任意一个外部地址，这一项照样判"通过"，而总结论会写成"三项都被挡住"。pi 在回报里也承认了这个局限，但结论文字没有体现出来。这样容易让人误以为外网已经被挡住了。
- **建议**：在白名单这一层（防火墙或代理）实现之前，这一项的结论单独标成"**部分验证**"，不要计入"通过"，并在总结论里写明"外网白名单层还没有实现"。

## 3.【中】"能调用模型"这一项的判断标准太宽
- **位置**：`scripts/decoy/checks.py:154-175`
- **为什么重要**：现在的标准是"退出码为 0，并且有任何输出"就算通过。但很多 CLI 在没登录或额度用完时，也会打印一段错误信息，然后正常退出。这种情况会被误判为"模型能用"。
- **建议**：提示词第 5 步已经要求 Agent 回答 `OK`。把判断标准改成"输出里出现这个约定好的回答"，最好换成一个每次随机生成的标记，防止 Agent 照抄提示词里的文字。

## 4.【低】操作手册里要更醒目地写出"别用 root 运行 Agent"
- **位置**：`scripts/wsl/setup-tandem-distro.ps1:193-201`
- **说明**：脚本最后提示了要建一个日常用户，但默认用户的配置要你手动去改。如果漏了这一步，Agent 就会以 root 身份运行。建议在操作手册里把这一步写成必做项，并在诱饵测试开始时检查当前用户：如果是 root，就直接拒绝运行。

## 结论
**修改后可以交给用户审核。** 第 1 条必须改，它直接关系到隔离是否成立。第 2、3 条建议这一轮一起改，第 4 条顺手改掉就行。
