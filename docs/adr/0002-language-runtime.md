## 背景
M1 开始写代码之前，必须先定下用什么语言。原因：
- 语言一旦定了，内核、外壳、测试、CI 都会跟着它走，以后再换代价很大。
- ADR-0001 已经定下"函数式内核 + 命令式外壳"，后台运行在 WSL2 里。

这个系统里的代码分两类，需求很不一样：

| | 内核（你主写） | 外壳（AI 主写） |
|---|---|---|
| 内容 | 状态流转、等级裁决、MOD-1 到 MOD-4 的数学模型 | 调 GitHub、发飞书卡片、启动和结束 Agent 进程、读写 SQLite、定时器 |
| 需要什么 | 写数学顺手；能写纯函数和测试；你**读得懂、讲得清** | 进程管理、网络请求、生态成熟；AI 写起来不容易出错 |

约束：
- 你要亲手写内核，所以**你对这门语言的熟悉程度**是重要因素。
- agent-autoloop 是 TypeScript 写的，用 Node 24 直接运行 `.ts` 文件，运行时零依赖。它是我们的参考设计。
- `learn/layering/` 里的分层例子是 Python 写的，你已经读过。

## 备选方案

### A. 全部用 TypeScript
- **做法**：内核和外壳都用 TypeScript，运行在 Node 上。
- **好处**：
  - 可以直接参考 autoloop 的代码，包括它的纯度检查测试、Agent 适配器、回执解析。
  - 类型系统适合写状态机：把 13 个状态写成联合类型以后，**漏处理某个状态，编译时就会报错**。
  - Claude Agent SDK 和 Codex SDK 都有 TypeScript 版（已核实，见下方"已核实的事实"）。
- **代价**：
  - 数学生态弱。MOD-1 要用 Beta 分布的分位数，MOD-2 可能要用优化求解器。JS 里有 jStat 这类库，但成熟度不如 Python【未核实精度】。也可以自己实现，但 Beta 分位数要用到不完全 Beta 函数的反函数，自己写并不简单。
  - 如果你不熟悉 TypeScript，写内核的同时还要学一门语言。

### B. 全部用 Python
- **做法**：内核和外壳都用 Python。
- **好处**：
  - 数学生态最好：`scipy.stats.beta.ppf` 一行就能算 Beta 分位数，优化、抽样、排队模拟都有成熟的库。
  - 你已经读过 `learn/layering` 的 Python 例子，纯度检查测试也已经有一个现成的版本。
  - Claude Agent SDK 和 Codex SDK 都有官方 Python 版（已核实）。
- **代价**：
  - autoloop 只能参考设计，不能直接复用代码，需要翻译。
  - 类型检查是可选的（mypy、pyright），状态机"漏处理"的检查要靠工具和写法来保证，不像 TypeScript 那样默认就有。

### C. 混合：内核用 Python，外壳用 TypeScript
- **做法**：外壳用 TypeScript，可以借用 autoloop 的代码；内核用 Python，借用它的数学生态。两边通过 JSON 通信，比如外壳把快照写成 JSON，交给 Python 内核，再读回"新状态 + 动作清单"。
- **好处**：
  - 两边各用最合适的生态。
  - **语言边界会从物理上强制内核纯净**：内核根本拿不到外壳的库，数据合同也必须写成明确的 JSON 格式。
- **代价**：
  - 两套工具链、两套测试、两套依赖管理，CI 也要配两遍。
  - 跨语言调试更麻烦；每次决策都要启动一次 Python 进程，或者维护一个常驻进程。
  - 对一个人维护的项目来说，复杂度明显更高。

## 已核实的事实（2026-11-07 查官方文档）
| 事实 | 结论 | 来源 |
|---|---|---|
| Claude Agent SDK 支持哪些语言 | Python（`claude-agent-sdk`，需要 3.10 以上）和 TypeScript（`@anthropic-ai/claude-agent-sdk`）。其他语言可以通过 `claude -p --output-format json` 以命令行方式调用 | [官方文档](https://code.claude.com/docs/en/agent-sdk/overview) |
| Codex SDK 支持哪些语言 | TypeScript（`@openai/codex-sdk`，需要 Node 18 以上）和 Python（`openai-codex`，需要 3.10 以上）。较旧的文档把 Python 版称为"实验性"，现在的文档已经列为正式安装方式【稳定程度以实际试用为准】。PyPI 上的 `python-codex-sdk` 是第三方移植版，不是官方的 | [官方文档](https://developers.openai.com/codex/sdk) |
| JS 里的 Beta 分位数精度 | **没查到** jStat 的精度数据。stdlib-js 有一个 `betaincinv` 的提交。这类函数在其他语言的库里也出现过精度问题 | 搜索结果不充分，【未核实】 |

结论：**两门语言都能调用 Claude 和 Codex**。"TypeScript 才有 SDK"不再是选 TypeScript 的理由。

为了快速推进，这次由 Claude 挑刺，没有再请其他 Agent。（如果你想要，可以补一轮。）

你的回应：**全部接受**。第 1 条的理由按建议写法采纳：熟悉 Python，可以把学习精力留给建模和架构；Python 的数学生态服务于内核；两家 AI 的 SDK 都支持 Python。

## 决定（AI 草稿，你已确认）
内核和外壳全部用 Python。工具链如下：
- `uv`：管理 Python 版本和依赖，锁文件提交进仓库；
- `pytest`：测试；
- `pyright`（严格模式）：类型检查，作为 CI 的必需检查；
- `ruff`：代码风格检查。

内核的纯度检查沿用 `learn/layering/test_core.py` 的做法：检查内核目录里 import 了哪些模块，碰到外部模块就报错。

## 代价（AI 草稿）
- 状态机"漏处理就报错"要靠 pyright 和固定写法来保证，不是语言默认就有的。忘了写 `assert_never` 的地方就会漏掉。
- autoloop 的代码不能直接复用。
- Python 的运行速度比 Node 慢。对这个系统来说影响不大，因为瓶颈在等 AI 回复，不在计算。
