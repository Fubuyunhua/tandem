# 任务：ADR-0001 定稿前的终审

ADR-0001 已经根据 11 条评审意见改过一轮，用户也逐条做了决定。现在请你在用户最终审核之前，对**整套最终方案**做一次终审。

## 要读的文件（只读，不要修改）
- `docs/adr/0001-overall-architecture.md`：ADR 定稿候选（"决定 / 代价 / 重新考虑的信号"三节是 AI 草稿）
- `docs/design/task-lifecycle.md`：任务状态流转（以**第六版**及其后的补充为准，前几版是讨论过程）
- `docs/adr/reviews/0001-summary.md`：11 条评审意见和用户的回应，包含用户的原话
- `docs/PRD.md`：v1.1

## 独立性要求
- **不要读** `docs/adr/reviews/` 下以 `0001-final-` 开头的其他文件，那是其他评审者这一轮的输出。这一轮要求各评审者独立完成。
- 之前的评审文件（`0001-codex.md`、`0001-pi.md`、`0001-discussion-codex.md`）可以读。

## 重要约束
- **决定权在用户。** 用户在练习架构设计和批判能力。已经做出的决定，你可以指出它的风险，但不要假装它没有被决定过，也不要替用户做新的决定。
- 没有核实的事实，标注【未核实】。

## 请检查这四件事
1. **前后一致**：ADR、状态流转、PRD、评审汇总这四份文件之间，有没有互相矛盾的地方？请具体写出哪个文件的哪一句和哪一句冲突。
2. **转述是否忠实**：ADR 里标为"你的决定"的内容，以及 AI 草稿那三节，有没有歪曲用户的原话，或者夹带了用户没做过的决定？请对照评审汇总里的原话来核对。
3. **能不能落地**：按 M1 的范围（WSL2、只接 Claude、只接带 agent 标签的 Issue），这套设计能不能实现？有没有哪一处在 M1 根本走不通？
4. **信号能不能观察**："重新考虑的信号"表里的每一条，系统能不能自动测出来？如果需要额外记录什么数据，请写出来。

## 输出格式
- 最多 8 条，按严重程度从高到低排列。每条写：
  - **问题**：一句话
  - **证据**：文件名 + 原句
  - **建议**
  - **严重程度**：高 / 中 / 低
- 最后用一句话给出结论："可以定稿" / "改完以下几条后可以定稿" / "不建议定稿"，并说明理由。
- 写到 `docs/adr/reviews/0001-final-<你的名字>.md`（codex、pi 或 agy）。
- 写完后在终端只回复一行：`DONE`
