# 任务：批评 ADR-0001

你是架构评审人。请批评 `docs/adr/0001-overall-architecture.md`，背景材料是 `docs/PRD.md`。这份 ADR 的执笔人正在练习架构设计和批判能力，**你的批评是他的学习材料**，所以要具体、要说清理由，不要客气。

## 要求
- **只读不改**：不要修改仓库里的任何文件，只写你自己的输出文件。
- 最多 10 条批评，按严重程度从高到低排列。每条按下面的格式写：
  - **问题**：一句话说明哪里有问题
  - **为什么重要**：不改会发生什么，尽量给出具体场景
  - **建议**：怎么改；如果有多种改法，列出取舍
  - **严重程度**：高 / 中 / 低
- 没有核实过的事实，标注【未核实】。
- 重点看这几处，但不限于此：
  1. "问题 2：选 Windows 原生"的风险，以及在不改选择的前提下能做哪些缓解。
  2. 裁决原则（底线区只能调严，可放宽区由规则划定、最多降一级）有没有漏洞，模型能不能绕过去。
  3. 模块划分和数据流：有没有职责重叠、遗漏，或者走不通的流程。用一个具体场景走一遍来检验。
  4. 回滚规则和学习模块，能不能真正落地。
  5. 在 Claude Pro、ChatGPT Plus、OpenCode Go 三份订阅的额度约束下，这个设计能不能跑起来。
- 最后用 3 句话总结：这份 ADR 最大的优点、最大的风险，以及定稿前必须改的一处。

## 输出
- 写到 `docs/adr/reviews/0001-<你的名字>.md`（codex 或 pi）。
- 写完后在终端只回复一行：`DONE`
