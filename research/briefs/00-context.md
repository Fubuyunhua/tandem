# 共同背景（三位调研员都要读）

日期：2026-11-04。委托人是一名独立开发者（Windows，日常用 Claude Code、Codex、pi、Antigravity，并用 herdr 这个终端多路复用器同时管理多个 coding agent）。

他遇到的问题：
1. **手写代码能力得不到锻炼**；AI 写得太快，他读不过来、理解跟不上。
2. **审核瓶颈**：AI 产出太快，不能全部放手交给 AI，但也不可能每一处都逐一 review 和决策。
3. 他注意到很多厂商/开发者在谈"AI 项目自动化流程"：让 AI 自己做决定、跑 CI，并**自动判断哪些可以直接决定、哪些需要人工判断**。
4. 他想打造**属于自己的自动化流程**，不只用于写代码，还希望推广到生活中。

本次是一次三方分工调研，最后由协调者（Claude）汇总成一份报告。你只负责自己那一块，不要越界写别人的部分。

## 统一产出要求

- 语言：中文（专有名词、产品名保留英文）。
- 写到 `research/out/<你的名字>.md`，不要修改项目中的其他任何文件。
- 结构：
  1. **一句话结论**
  2. **关键发现**：每条都要写明来源（链接 + 发布时间/版本）。能联网就联网检索，优先一手来源（官方文档、官方博客、论文、作者本人文章），并优先 2025–2026 年的资料。
  3. **对委托人的可落地建议**：具体到他可以照着做的步骤、配置或规则；不要空话。
  4. **争议与不确定**：哪些说法证据薄弱、存在争议或可能已过时。
  5. **参考来源列表**
- 篇幅：约 2500–5000 字。宁可少而准，也不要堆砌。
- **诚实标注**：如果你无法联网，或某条来自记忆而非检索，请在该条后标注【未核实】。不要编造链接、数据或引文。
- 完成后，在对话中只回复一行：`DONE research/out/<你的名字>.md`
